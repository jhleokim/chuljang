# 설치 없는 영수증 수집

웹 로그인 후 **출장 날짜를 복수 선택하고 사용한 서비스에 로그인**한다. 로그인 성공을 자동 감지해 조회로 이어지며, 별도 수집 시작이나 로그인 완료 버튼은 없다. 날짜 선택이 바뀌면 연결된 서비스의 조회 작업에 자동 반영한다. 확장 도구나 로컬 프로그램 설치는 필요 없다. Chrome 프로필 로그인은 서비스별 인증을 대신하지 않는다.

## 구현된 구성

- Sites의 /api/collection은 인증된 사용자 ID로 수집 서버에 요청한다. 비밀키를 브라우저에 전달하지 않는다.
- Cloudflare Worker server-collector/와 Browser Run이 원격 브라우저를 실행한다. Durable Object는 사용자·서비스별 작업, 암호화된 로그인 상태와 수집 대기 내역을 보관한다.
- 서비스의 로그인 버튼을 누르면 해당 날짜 조회와 인증 상태 보관을 승인하고 원격 로그인 창을 연다. 사용자가 공식 화면에서 로그인과 필요한 추가 인증을 마치면 성공 표식을 자동 확인한다. 별도 완료 조작 없이 구현된 조회 어댑터로 이어진다.
- 이후 유효한 로그인 상태를 재사용한다. 연결 해제는 로그인 상태와 대기 내역을 삭제하고 실행 브라우저 종료를 요청한다.
- 날짜 선택은 짧은 대기 후 자동 반영한다. 로그인 중에는 조회할 날짜를 갱신하고, 이전 날짜를 조회 중이면 작업을 중단한 뒤 새 날짜로 이어간다. 날짜를 모두 해제하면 진행 중인 조회를 중단한다.
- 선택한 정확한 날짜 집합을 작업·패킷·저장 검증에 유지한다. 이용일이 불명확한 내역은 검토 대상으로 남긴다.
- 페이지를 닫아도 서버 작업과 대기 내역은 유지된다. 웹이 열려 있을 때 결과를 받아 자동 저장하고, 저장 성공 또는 명시적 제외 후 서버 대기 내역을 삭제한다. 새로고침하면 미처리 결과가 다시 전달된다.

## 범위와 현재 한계

현재 화면의 서비스는 KTX·코레일, 티머니 지하철·시내버스, KOBUS 고속버스다. 로그인 연결과 자동 수집 구현 상태를 구분한다.

- **KTX:** `server-collector/korail.ts`와 `history-dom.ts`가 공식 영수증 조회 화면과 응답을 대조한다. 선택한 날짜를 하루씩 조회하고 더보기 페이지를 끝까지 확인하며 취소 내역을 제외한다. `receipt-pdf.ts`는 선택 영수증 인쇄 화면을 PDF로 보관한다. 조회 응답 오류, 승차권 건수 불일치, 미처리 페이지나 PDF 생성 실패를 조회 완료로 처리하지 않는다. 날짜별 재개·페이지 이동·영수증 추출·PDF 경로는 합성 테스트를 통과했으나 **실제 회원 계정의 로그인부터 저장까지는 아직 통합 검증하지 않았다.**
- **티머니 지하철·시내버스, KOBUS:** 공식 로그인 성공 후 회원 조회 화면의 필드·표·스크립트 구조를 확인한다. 현재 상태는 `adapter_pending`이며, 전용 조회·페이지 이동·영수증 수집이 완성된 상태가 아니다. 로그인 성공을 수집 성공으로 표시하지 않는다. 티머니 대중교통과 KOBUS 고속버스는 각각 별도 연결이다.
- **항공·카카오 T·쏘카:** 발급된 이미지/PDF 가져오기를 사용할 수 있다. 기존 항공·쏘카 기업 웹 실험 연결은 회원 계정의 자동 수집을 검증한 서비스가 아니다.

티머니 일반 내역 조회는 회원 계정에 등록된 선불·모바일 티머니카드가 대상이다. 공식 FAQ의 조회 가능 기간은 조회일 기준 D−367일부터 D−2일까지이며, 오늘·어제 내역은 조회 결과 없음과 구분해야 한다. Android 모바일티머니는 앱과 홈페이지의 본인인증 명의가 같으면 홈페이지 가입 시 카드가 자동 등록될 수 있다. 은행·카드사 발행 신용·체크카드의 후불교통 내역은 발행 카드사에서 제공한다. 가입 전 내역은 카드 증빙·본인인증을 거치는 별도 신청으로, 즉시 수집 대상이 아니다. [티머니 공식 FAQ](https://pay.tmoney.co.kr/ncs/pct/cuscent/ReadFaqBscList.dev), [공식 사용 내역 조회](https://pay.tmoney.co.kr/ncs/pct/mtmn/ReadTrprInqr.dev)

지정 정산 양식의 파일 저장과 웹메일 첨부·전송은 아직 사용할 수 없다. 현재 제공하는 저장은 수집한 영수증과 원본을 사용자 공간에 보관하는 기능이다.

## 운영 설정

1. Browser Run과 SQLite Durable Object를 사용할 수 있는 Cloudflare 계정으로 server-collector/wrangler.jsonc의 계정 ID를 설정한다.
2. wrangler secret put COLLECTOR_SECRET --config server-collector/wrangler.jsonc 으로 충분히 긴 임의 비밀키를 설정하고 Worker를 배포한다.
3. Sites 환경에 CHULJANG_COLLECTOR_URL과 같은 키의 CHULJANG_COLLECTOR_SECRET을 설정한다. 비밀키는 저장소에 넣지 않는다. 로컬 개발은 무시된 .dev.vars에 설정한다.
4. 로그인 상태와 영수증 대기 내역은 AES-GCM으로 암호화하며 사용자·서비스·저장 키를 인증 데이터로 사용한다. 키 변경 시 기존 데이터가 해독되지 않으므로 연결 해제·재연결 계획이 필요하다.
5. 서버 요청은 본문·타임스탬프 HMAC으로 인증한다. 사이트 API는 인증·소유자 분리·Origin 검사를 적용한다.

여러 서비스는 25초 간격으로 시작하며 일시적 연결 실패는 제한된 횟수로 재시도한다. 브라우저 실행은 계정 한도를 사용한다. 별도 요금제 변경은 수행하지 않았다. 서버 대기 내역은 저장 확인·제외·연결 해제 전까지 남는다. 수동 파일/텍스트 초안은 페이지 메모리에만 있다.

## 검증

- node --experimental-strip-types --test tests/*.test.mjs: 실제 상태 클래스의 권한·중복 요청·취소·원자적 저장·계정 분리와 날짜/인식 회귀 검사.
- node --experimental-strip-types --test tests/transit-collection.test.mjs: 합성 코레일 화면·응답으로 날짜별 자동 반영, 더보기, 취소 제외, 식별번호별 추출, 공식 인쇄 화면의 PDF 생성 경로를 검사한다. 실제 회원 계정 통합 테스트를 대신하지 않는다.
- node tests/api-smoke.mjs: 로컬 사이트 API의 인증·날짜·수집 요청 검증.
- node --experimental-strip-types tests/collector-server-smoke.mjs: .dev.vars의 배포 서버에 일회용 연결을 만들어 로그인 링크와 해제를 검사한다. 브라우저 사용량이 발생하며 실제 회원 계정은 사용하지 않는다.
